# Claude Code config background

Context for `home/claude/` (distributed to `~/.claude/`), the hosts'
`claude/settings.json`, and their tests. How these files get into
`~/.claude/` is in `.claude/rules/nix-hosts.md`.

## Safety layers (`hosts/MacBookPro-minami/claude/settings.json`)

`permissions.defaultMode` is `"auto"`; these layers make that acceptable.

- **sandbox** (Seatbelt): writes are limited to the working directory and
  the session temp dir; `~/.ssh`, `~/.aws`, `~/.gnupg` and GitHub/AWS token
  env vars aren't readable.
- **`excludedCommands`**, each chosen by actually trying it in this repo
  and in typical npm/uv work:
  - `nix`, `darwin-rebuild`, `nh`, `,`: talk to the nix daemon socket.
  - `docker`: talks to the Docker socket.
  - `make`: each target fetches its tool via `nix run`.
  - `gh`, `terraform`: Go binaries fail TLS verification under Seatbelt (a
    known issue in the official docs); `terraform validate` failed to load
    plugins here too.
  - `git push` and other remote operations: SSH can't read `~/.ssh`.
  - `git init` (and `uv init`, which calls it): the sandbox always denies
    writes to `.git/config` and `.git/hooks`, since both can lead to code
    execution. `git remote add`/`git config` fail for the same reason but
    are rare enough not to exclude; Claude Code retries them outside the
    sandbox and the auto-mode classifier decides.
  - An exclusion only applies when the command runs alone: chained with
    `&&`, piped, or with `git -C`, it runs inside the sandbox.
- **Write allowlist for package caches** (`~/.npm`, `~/.cache/uv`, pip,
  deno): without it `npm install`/`uv add` fail. Only the caches are
  allowed, rather than excluding the package managers, so postinstall
  scripts still run sandboxed.
- **`permissions.deny`** keeps the file tools away from the same secret
  directories. This repo's `.claude/settings.json` does the same for
  `services/*/.env` and `terraform/local/terraform.tfstate*`.
- **`guard-bash.sh`** (PreToolUse) is the last layer; see below.

## Other settings

- `autoMode.environment` tells the classifier facts about this machine
  (personal Mac, own GitHub account, local-only services, the scope of
  `terraform/local`, where secrets live). Without it the classifier treats
  local service operations like external ones. It only states facts; it
  doesn't override decisions with allow rules.
- `cleanupPeriodDays` is 180 (default 30): it bounds both `/resume` and
  how far back past sessions in `~/.claude/projects/` can be read.
- Removing a key from the repo's `settings.json` doesn't remove it from
  `~/.claude/settings.json` (the activation only merges). To turn
  something off, change its value instead (e.g.
  `"sandbox": {"enabled": false}`).

## `hooks/guard-bash.sh`

- Blocks recursive `rm` on `/`, the home directory or `/Users`, and force
  pushes other than `--force-with-lease`, regardless of permission mode.
- It pattern-matches the command text only: it doesn't see through
  `sh -c`, xargs or scripts. It's a guard against slips, not a boundary.
  Further checks (`git clean -x`, Docker volume removal, pushes to main)
  were considered and declined.
- Regression tests live in `tests/claude-scripts.sh` (also run by CI);
  add a case there for any new pattern.

## `statusline.sh`

- Shows the claude.ai 5-hour rate limit when present; with an API key or a
  local Ollama model (`claude-q38`/`claude-q3cn`) it shows session cost
  instead.

## `hooks/herdr-agent-state.sh`

- Generated by `herdr integration install claude`; don't edit it by hand.
  After a herdr update changes the integration, re-run that command and
  copy the result here.
