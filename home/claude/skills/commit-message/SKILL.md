# コミットメッセージの規約

## 適用範囲を先に確かめる

最初に`git log -10 --format='%s%n%b'`で既存の書き方を確認する。

- 英語のリポジトリや、Conventional Commitsなど別の形式が定着しているリポジトリ
  (他者のリポジトリのcloneなど)では、この規約ではなく**そのリポジトリの形式に従う**
- 既存の履歴が日本語の「<対象>: <要約>」形式か、履歴がまだ無い場合に、以下を適用する

## 件名(1行目)

- 形式は`<対象>: <何をするか>`。対象はディレクトリ名、ツール名、ファイル名など、
  変更の場所がひと目で分かる語にする(例: `nvim`、`CI`、`casks`、`README.md`)
- 変更が1か所にまとまらない場合は、対象を付けずに要約だけでよい
- 要約は「〜する」「〜を直す」「〜へ置き換える」のような動詞の終止形で終え、句点は付けない
- 何を変えたかが件名だけで分かるように書く。「修正」「更新」だけの件名にしない

## 本文

件名との間に空行を1行入れる。1行は全角40字程度で折り返す。

1. **理由と背景**を最初に書く。何が問題だったのか、なぜその変更が必要なのかを書く。
   バグの修正なら、原因(どの設定がどう働いて何が起きていたか)まで書く
2. 変更点が複数あるときは、`- `の箇条書きで列挙する。
   それぞれに、単なる事実ではなく判断の理由を添える
3. **確認した内容**を書く。何をどう実行して確かめたかを「〜を確認済み」の形で書く。
   確認できていないこと(CIでしか確かめられない等)は、そうと明記する
4. 関連するコミットは短いハッシュで示す(例: `(d6c38ec)`)

差分を読めば分かること(どのファイルの何行目を変えたか)は書かない。

Claude Codeが作ったコミットには、ハーネスが指定する`Co-Authored-By`の行を末尾に付ける。

## プルリクエスト

本文は、コミットの本文と同じ構成(理由と背景、変更点、確認した内容)で書く。
コミットが複数ある場合は、個々のコミットの説明を並べるのではなく、PR全体として1つの説明にまとめる。
